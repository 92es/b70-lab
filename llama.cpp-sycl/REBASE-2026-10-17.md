# Fork rebased onto upstream llama.cpp (r67c, 2026-10-17)

The tuned SYCL fork (based on upstream from 2026-09-29) was rebased onto upstream master `797de63b2`
(2026-10-17, 474 commits later) and validated model by model against the runtimes in daily use.

## What the new tree contains

- upstream master `797de63b2`, which already includes our MXFP4 MoE work (#29809) and the pinned tensor-split
  all-reduce (#29604), so those two local commits were dropped
- `set_tensor_2d` for SYCL buffers (still in review upstream, #30358)
- the four upstream candidates in `upstream-candidates/` (Q8_0 16-byte loads, Q8_0 GLU fusion, ADD -> RMS_NORM -> MUL
  fusion, Xe2 FA decode split)
- the fork tuning described in `fork/` (wide f32 mat-vec, Q8_0 MoE reorder, top-k MoE, small fusions, cross-card
  pipeline, Q6_K wide dot, DeepSeek V4 sparse FA / indexer / placement fixes)
- the GLM-5.3 kernels (batched Q4_K/Q5_K/Q6_K MLA mat-vec, IQ2_S / IQ3_S / IQ2_XXS MoE local-memory kernels), so GLM
  no longer needs its own branch

## Choices made during the rebase

| Area | Kept | Why |
|---|---|---|
| Q5_K reorder mat-vec | upstream (#29375, with fused GLU) | replaces the fork's Q5_K wide dot; only a 27B Q6 entry used that one (not re-measured yet) |
| Qwen3.8-Flash-Next MTP head | upstream implementation | plus two local fixes, below |
| Q8_0 MoE expert reorder | upstream reorder function (same layout as the fork's) | kernel selectable: `GGML_SYCL_MMID_Q8_0_WIDE=1` (default, fork's 16-byte path) or `0` (upstream's order-preserving path) |
| MoE `mul_mat_id` host path | fork's routed / small-fused path + upstream grouped XMX GEMM (#29245) | as already merged for GLM |
| IQ2_XS / IQ3_XXS local-memory MoE kernels | fork kernels, sign tables dropped | upstream now derives the signs arithmetically |

Two upstream gaps had to be fixed locally for the Flash-Next MTP entry, which loads the MTP head from a separate
"shared" draft GGUF (no token embeddings or output head of its own):

1. loading such a draft failed (`token_embd.weight not found`): the draft now borrows the target's token embeddings
   and output head through its `ctx_other` link;
2. the draft's first decode then hit `GGML_ASSERT(buffer)`: the MTP layer runs dense attention when its compress
   ratio is 0, so the k-pool inputs were set without being in the graph. They are now built only when the layer uses
   the sparse (QSA) path.
